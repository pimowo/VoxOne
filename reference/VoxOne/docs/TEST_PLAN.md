# TEST PLAN

## Current milestone status

### StationStore v2 logical coverage

- Missing NVS creates and persists the three factory stations; a subsequent
  boot loads the same ordered blob.
- Add/update/remove and move-up/move-down persist immediately; reordering does
  not change stable IDs.
- Removing the default repairs it to the first station or zero. Removing the
  selected/playing station stops radio, clears metadata and selects the first
  remaining station without auto-start.
- A valid empty list is safe for RadioList, next/previous, radio start, WWW and
  the empty playlist endpoint; adding the first station restores a default.
- Invalid magic/version/CRC/count/length/field/duplicate ID falls back to
  verified factory defaults.
- WWW play routes through App. RadioList and next/previous use persisted order.
  yoRadio playlist rows use the same order and `play N` maps position N to
  the stable internal ID.
- Factory reset restores all three defaults.

This checkpoint covers RadioService/StationStore, ICY metadata, RadioList
placeholder behavior, always-on WWW, five Wi-Fi profiles with AP fallback,
MQTT and ha_yoradio command/status/volume/playlist, PLAY_MEDIA/TTS override,
the 1500 ms duplicate-stop guard, RADIO/BT double-click and logical BT
CONNECTED/DISCONNECTED switching. The automatic BT path remains
hardware-test-pending until VoxOneBT is connected.

MAIN has no local Bluetooth lifecycle. BT uses BtLink and
RemoteBluetoothBackend; VoxOneBT is a separate module. HOME strings include
Radio WEB, Bluetooth, Czekam na połączenie and radio format such as 128 MP3.
Supported feature variants are TTS-only, TTS + Radio, TTS + BT and TTS +
Radio + BT.

### Stable MP3/display baseline

- [x] DisplayService rendering is owned by DisplayTask on core 0; App performs
  no ST7789 SPI rendering.
- [x] MP3 input buffer is 8192 bytes and one network read is capped at 4096
  bytes while still bounded by available data and free buffer space.
- [x] One RadioService PCM write is capped at 4608 bytes; partial-write/error
  handling and PcmGainOutput's internal 256-byte processing remain active.
- [x] I2S TX uses the new driver with DMA 8 x 512 frames.
- [x] Shared output gain preserves logical volume 0..100 and caps maximum gain
  at Q15=16384 (about -6.02 dB).
- [x] Hardware playback is stable for tested MP3 streams at 128, 256 and
  320 kbps with the active ST7789 UI.
- [ ] Long-duration regression: HTTP and HTTPS, metadata scrolling, clock,
  RadioList, rapid volume changes, Wi-Fi reconnect and repeated station changes.

## PLAY_MEDIA - planned, pending hardware validation

PLAY_MEDIA is a temporary override and physical third audio owner, not a normal
user source. It may play speech generated by HA or ordinary media. Home
Assistant owns the request queue; VoxOne owns suspend, completion, cleanup,
volume restoration and base-source restoration.

- [ ] RADIO -> PLAY_MEDIA CURRENT -> RADIO
- [ ] RADIO -> PLAY_MEDIA FIXED -> RADIO
- [ ] BT -> PLAY_MEDIA CURRENT -> BT
- [ ] BT -> PLAY_MEDIA FIXED -> BT
- [ ] STOP -> PLAY_MEDIA -> STOP
- [ ] PLAY_MEDIA URL/Wi-Fi/decoder errors perform restore
- [ ] previous logical volume 0..100 is restored exactly
- [ ] FIXED volume respects physical/max output limit
- [ ] repeated HA PLAY_MEDIA requests do not leak heap
- [ ] repeated BT/RADIO overrides do not degrade playback
- [ ] WebSocket/MQTT remain responsive during PLAY_MEDIA
- [ ] watchdog is not triggered
- [ ] AudioOutputManager has the correct owner after every outcome

All PLAY_MEDIA acceptance criteria remain pending until hardware tests are complete.
