# Zasady pracy z VoxOne

- Przed każdym zadaniem przeczytaj `docs/TODO.md`; jest to jedyna kanoniczna lista zadań projektu.
- Nie twórz dodatkowych list TODO ani roadmap w innych plikach. Dodawaj nowe prace do `docs/TODO.md`.
- Po ukończeniu i odpowiedniej weryfikacji usuń wykonane zadanie z TODO; przy częściowym wykonaniu zostaw wyłącznie niewykonaną część.
- Nie usuwaj zadania wymagającego testu sprzętowego tylko dlatego, że build przeszedł. Przed zakończeniem pracy sprawdź, czy TODO odpowiada rzeczywistemu stanowi projektu, i opisz w raporcie zmiany w TODO.
- `reference/` jest tylko do odczytu. Nie modyfikuj jej.
- Nie commituj, nie taguj ani nie pushuj bez wyraźnego polecenia użytkownika.
- Techniczny checkpoint nie zmienia `VOXONE_VERSION`. Preferuj małe etapy zamiast szerokich refaktorów.
